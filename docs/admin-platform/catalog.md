**Модуль:** Каталог
**Статус в коде:** частично существует — `CatalogService`, `SellerProductService`, `ProductPublicationService` (Rule Engine: `DRAFT → PUBLISHED → HIDDEN`), `CategoryService`
**Роли с доступом:** Admin (полный доступ ко всем товарам/категориям), Seller (только свои товары)

> Этот документ описывает исключительно управление каталогом (товары и категории) со стороны Административной платформы. Работа продавца как отдельной сущности (профиль, статистика, верификация) — в `sellers.md`. Остатки и резервирование — в `warehouse.md`. Продуктовая витрина для покупателя уже существует и этим документом не описывается.

## Назначение

Административный раздел Каталога — инструмент для админа управлять всем товарным ассортиментом платформы (создавать/редактировать категории, модерировать товары продавцов, управлять публикацией) и для продавца — управлять собственными товарами в рамках уже существующего workflow публикации.

## Уже существующая бизнес-логика (не переизобретается)

- **Публикация товара** — Rule Engine (`ProductPublicationService`, правила `BootstrapDraftRule`, `SellerPublishRule`, `SellerHideRule`): `DRAFT → PUBLISHED → HIDDEN`. Прямой переход `DRAFT → HIDDEN` уже запрещён политикой.
- **Категории** — плоский список (`public.categories`: `id, name, slug, description, image_url, sort_order, is_active`), обслуживается `CategoryService`/`SupabaseCategoryRepository`. Сегодня 8 категорий, без вложенности.
- **Данные товара** — `ProductDTO` (`id, name, slug, description, price, currency, unit, imageUrl, stock, inStock, categoryId`). Изображения категорий сегодня — гибрид: `image_url` из Supabase Storage (bucket `category-images`, приоритет) либо локальный fallback-ассет, либо честная заглушка «Нет фото» при отсутствии обоих (актуальное, недавно исправленное поведение — см. `src/routes/index.tsx`).

## Структура административного раздела

```
Каталог
├── Категории
│   ├── Список (sort_order, is_active, кол-во товаров)
│   └── Форма категории (название, slug, изображение, сортировка, активность)
├── Товары (вид Admin — все продавцы; вид Seller — только свои)
│   ├── Список (фильтр по категории, статусу публикации, продавцу)
│   ├── Модерация (для Admin — просмотр товара продавца до/после публикации)
│   └── Форма товара (название, цена, категория, изображения, единица измерения)
└── Стандарты качества карточки
    └── Обзор результатов marketplace-ai (см. «Связь с ИИ» ниже) — если/когда включено
```

## Бизнес-логика

Административный Каталог **не вводит новых правил допуска** — он предоставляет UI над уже существующим `ProductPublicationService`. Единственная новая для Административной платформы возможность — **административная модерация**: право Admin принудительно скрыть товар продавца (`HIDDEN`) в обход обычного цикла продавца, если товар нарушает стандарты (см. `server/domain/marketplace-standards/` — уже существующий, пока преимущественно инфраструктурный набор сервисов для контент-стандартов, стандартов качества, стандартов категорий). Это действие должно быть отдельным правилом в том же Rule Engine (`AdminForceHideRule` или аналогичное), а не отдельным путём в обход политики публикации.

Управление категориями (создание/сортировка/деактивация) — новая функциональность, которой в коде сегодня нет вообще (есть только read-путь `CategoryService.listCategories()`); её нужно спроектировать по аналогии с уже существующим паттерном `SellerProductService` (create/update через Zod-валидацию → domain service → repository), не изобретая новый слой.

## События

Каталог должен публиковать в `IMarketplaceEventBus`:
- `product.published` / `product.hidden` — уже implicit в переходах `ProductPublicationService`, но сегодня **не публикуется как событие** (rule engine меняет статус, событие в шину не уходит) — это пробел, который Административная платформа обязана закрыть, если другие модули (например, ИИ-анализ качества, см. `ai.md`) должны реагировать на публикацию.
- `category.created` / `category.updated` — новое, для инвалидации кэша каталога на витрине (`staleTime: 5 * 60 * 1000` в `src/routes/index.tsx` уже подразумевает, что список категорий не мгновенно консистентен — событие не обязано быть real-time).

## Права доступа

| Действие | Admin | Seller |
|---|---|---|
| Просмотр всех товаров | ✅ | — (только свои) |
| Создание/редактирование своего товара | ✅ | ✅ |
| Публикация/скрытие своего товара | ✅ | ✅ (через уже существующий Rule Engine) |
| Принудительное скрытие чужого товара (модерация) | ✅ | — |
| Управление категориями | ✅ | — |
| Просмотр стандартов качества карточки | ✅ | 👁 (только по своим товарам, если включено) |

## Будущие расширения

- Вложенные категории (сегодня — плоский список, `sort_order` без иерархии).
- Массовые операции над товарами (bulk-редактирование цены/категории).
- Полноценное подключение результатов `marketplace-ai` (сегодня существует, но результат никем не читается — см. `ai.md` и известный пробел в `ARCHITECTURE_PRINCIPLES.md`) как источника подсказок для модерации.
